# 06-任务卡插件标准：加一个任务 = 加一个文件夹

## 1. 起因：一个任务定义散在三个文件里

加第四张任务卡之前，"任务"这件事在代码里有**两个家**：

- `training/train_multitask.py`：类别名表 `TASK_SPECS`、`num_classes=4` 写死两处、
  `cls_w=[1.3,1,1,1]` / `act_w` 写死、`max_steps=4` 写死、三个数据集 import 写死；
- `examples/example_multitask.py`：`TASK_STYLE` / `TASK_LABEL` 又抄了一遍类别名与配色。

后果不是"麻烦"，是**静默出错**：改一处漏一处就是"训练用 4 类、推理用 5 类"，
或者类别改了名但渲染层还按老的顺序取颜色。

## 2. 唯一声明点

`dtseek/tasks/plugin.py` 定义两样东西：

```python
TaskSpec(name, label, classes,            # 类别体系（index 0 必须是背景类）
         max_steps, emission,             # 最多发射几个切片 / single | pair
         max_len, segment_policy,         # 编码窗口 / 推理怎么切段（sentence | window）
         annotate_all, identity_labels,   # 切片必须标全 / 类别是匿名身份槽
         cls_weight_bg, span_weight, action_weight)
TaskCard  # 协议：spec + build_dataset(target_samples, seed) [+ probe_units()]
```

`classes` 是 `TaskClass(name, label, color)` 的元组，**index 0 约定为背景类**。
展示名与终端配色也在同一处 —— 推理端不再有第二份类别定义。

`TaskSpec.__post_init__` 立刻校验（名字格式、至少两类、类别名不重复、
成对任务的 `max_steps` 必须为偶数、`max_len` 落在 8..128…），并且**一次报全部问题**，
不修一个报一个。

**四个容易踩的字段**：

- `max_len` 是**每个句段的编码窗口**。默认 64；人物追踪用 120（基座支持到 128），
  因为跨句共指需要多轮上下文。
- `segment_policy` 决定**推理时怎么把长文切给这张卡**，它必须与训练口径一致 ——
  `GenericTaskDataset` 是按 `max_len` 整段编码的。详见
  [10-冻结基座与训练推理口径一致性](10-冻结基座与训练推理口径一致性.md)。
- `annotate_all=True` 表示"样本里出现的切片必须全部标注"。此时样本超出 `max_steps`
  会**直接抛错**而不是静默截断 —— 漏标一半却还训练模型"在这里收束"是错的监督信号。
- `identity_labels=True` 表示类别是**匿名身份槽**（人物1/人物2…）而不是语义类别。
  此时 `evaluate_task` 会额外报 `first_mention_acc` / `repeat_mention_acc` / `cluster_f1`，
  因为 id 本身是任意的，真正要测的是"同一实体的多次提及有没有落在同一个 id 上"。

## 3. 加一个内置任务

```
src/dtseek/tasks/builtin/<任务名>/
├── __init__.py     # 声明 spec + CARD，末尾 register(CARD)
└── dataset.py      # build_dataset(target_samples, seed) -> [{text, spans:[{label,start,end}]}]
```

再在 `tasks/builtin/__init__.py` 里 import 一次（import 即注册）。

训练脚本、示例、探针**一行都不用改**：它们全部从注册表读
`num_classes` / `max_steps` / 损失权重，从 ckpt 里的 spec 快照读类别名与配色。

## 4. 加一个第三方任务（不改 DTSeek 源码）

在自己的包里声明 entry point：

```toml
[project.entry-points."dtseek.tasks"]
my_task = "my_pkg.my_task:CARD"
```

`all_tasks()` 会扫描并注册它。`tests/test_task_plugin_entrypoint.py` 真的造了一个
装了 entry point 的临时发行包走 `importlib.metadata` 验证这条路 —— 不是打桩。

## 5. ckpt 快照与 fail-closed

训练时把每张卡的 `spec.to_snapshot()` 写进 ckpt。加载时 `check_ckpt_specs()` 逐项比对：
任务是否还在注册表、**类别名列表是否逐字且同序相同**、`max_steps` / `emission` 是否相同。
任何一项对不上就抛 `TaskSpecMismatch`。快照本身坏掉（版本不符、字段缺失、声明非法）
也归到同一个错误出口，不漏出底层构造异常。

**校验的粒度：缺字段 ≠ 值不同。**

| 情况 | 含义 | 行为 |
|---|---|---|
| 字段**缺失** | ckpt 早于该字段诞生，代码里的值就是当前行为 | 继承 + 打印提示 |
| 字段**值不同** | 真的口径漂移 | 报错 |

推理行为类的字段（`max_len` / `segment_policy` / `identity_labels` / `annotate_all`）
归**代码**；类别名、类别数、`max_steps`、`emission` 决定权重含义，归**快照**并严格比对。
引擎在通过校验后统一从注册表里的任务卡取推理行为。

这条粒度是踩出来的：一开始把"缺字段"也当漂移，结果旧 ckpt 全部加载失败；
反过来若把"值不同"也放过，人物追踪会在推理时被按句切开、整句一致率从 16.2% 掉到 0.8%。

## 6. 数据契约

所有任务的数据集都返回同一个形状：

```python
[{"text": str, "spans": [{"label": int, "start": int, "end": int}]}]
```

`spans` 为空 = 背景样本；`label` 是 `spec.classes` 的下标；`start`/`end` 是
**0-based 半开区间**。共用的编码/损失/指标在 `dtseek/tasks/runtime.py`。

## 7. 探针扩展点

任务卡可以声明 `probe_units()`，返回 `ProbeUnit(key, expected_class, words, carriers)`。
`dtseek/tasks/probe.py` 只认这个类型，不认识任何具体任务。

两条被实测打出来的纪律：

- **载体要覆盖无终止标点的裸词形态**。情绪任务只测带句号的载体时，
  裸词输入的定位会被截断（`开心` → 圈到 `开`）。
- **探针的句式要和训练句式不重合**。语义关系任务首批训练句级"对完整命中率"97.9%，
  词对级探针只有 25.4% —— 训练帧只有 14 个，模型背下的是"这个句式里两个词在第几个字"。
  帧扩到 36 个后左词起点从少数固定位置散开到 10 种偏移。

另外，探针报告**类别错**与**定位错**要分开算。合成一个数就分不清是"认成了另一种关系"
还是"词根本没找着"，而这两种失败的修法完全不同。

## 8. 重构纪律：等价性黄金值

搬文件、改 import 这类重构不能靠读代码断言"没改行为"。`scripts/dump_equivalence_golden.py`
把三样确定性观测量落盘到 `tests/golden/multitask_equivalence.json`：

1. `dataset_hash` —— 数据集构建器都是固定 seed 的确定性函数，内容必须逐字节一致；
2. `weight_hash` —— 每个模块**单独播种**构造，所以只取决于模块定义，与构造顺序无关；
3. `step_loss` —— eval 模式下关掉 dropout，是权重与数据的纯函数。

`tests/test_task_plugin_equivalence.py` 重跑该脚本并与黄金值比对。
三项都对上，重构才没走样。**基线数值不允许为了"让测试过"而修改。**

## 9. 当前已注册的任务卡

| 卡 | 类别数 | emission | max_steps | max_len | 切段 | 探针单元 |
|---|---|---|---|---|---|---|
| `pronoun` 人称代词 | 4 | single | 4 | 64 | sentence | 9 |
| `sentiment` 情绪倾向 | 4 | single | 4 | 64 | sentence | 199 |
| `ownership` 发言归属 | 4 | single | 4 | 64 | sentence | 26 |
| `relation` 词义关系 | 3 | **pair** | 4 | 64 | sentence | 539 |
| `idiom` 成语识别 | 2 | single | 4 | 64 | sentence | 2214 |
| `person` 人物追踪 | 8 | single | **16** | **120** | **window** | —（句级指标验收） |

默认训练集是 **pronoun / sentiment / relation / person** 四张：

- `ownership` 保留可用（`--tasks ownership`），但它的"用户/助手/第三方"是**预设角色**，
  已被 `person` 的匿名身份槽取代 —— 详见 [09](09-失败案例解剖：符号与模板痕迹.md)；
- `idiom` 代码保留但**默认不训**：它的类别由具体四字串决定、只能靠记忆，
  而每个成语只有约 1 条真实例句，换帧探针只有 43.3% 类别 / 15.0% 定位。

`relation` 是成对发射：连续两个切片构成一对（左先右后、共享类别），
成对关系由发射顺序隐式表达，解码器不用改。代价是要盯 `pair_odd`（吐奇数个切片 = 配对错位）。

## 10. 加任务检查清单

- [ ] `TaskSpec` 字段填全，`classes[0]` 是背景类，配色与类别一一对应
- [ ] `max_len` 按任务需要选（默认 64；要跨句上下文才调大），别超过基座的 128
- [ ] **`segment_policy` 必须与训练口径一致**：训练是整段喂的，若任务需要跨句状态就必须用
      `window`，否则推理按句切开会让状态在句边界清零
- [ ] 数据集返回统一形状，`start`/`end` 是 0-based 半开
- [ ] 数据集自带 fail-closed 校验：载体/背景句不得混入未标注的正例
- [ ] 每个正例词/词对/实体都有覆盖下限（情绪任务踩过 Zipf 长尾：句级 98% / 词级 43.7%）
- [ ] 样本切片数不超过 `max_steps`；要"标全"就置 `annotate_all=True` 让超长样本响亮失败
- [ ] `probe_units()` 用**与训练不重合**的句式；没有"词+载体"形态的任务改用句级指标
- [ ] 如果类别是匿名的（id 可任意重命名），置 `identity_labels=True` 并看
      `repeat_mention_acc` 而不是 id 正确率
- [ ] 跑完看**整句级**指标 `exact_match` / `slice_recall`，不要只看首切片
      （已经四次出现"首切片/句级很好、真实水平很差"）
- [ ] `python training/train_multitask.py --tasks <新卡> --epochs 2` 能跑通并打印出该卡的指标
- [ ] `pytest` 与 `ruff` 干净
