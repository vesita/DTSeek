# 01-DTSeek 决策模型架构探索与初级训练踩坑笔记

## 1. 背景与核心动机
- **背景**：针对非自回归决策引擎（如 TypeSafe Jev / Laya），传统方案通常将问题指示、`[MASK]` 选项与输入上下文强行拼为单序列输入 ModernBERT 等大模型。
- **痛点**：
  1. 无法应对长文本多任务（每次新增一个任务都需要重新遍历整篇长文本）；
  2. 选项与输入 Tokenizer 强绑定，无法做到即插即用更换专用词表；
  3. 小模型（0.1B~0.3B）容易出现类别过度自信、概率坍缩现象。
- **创新构想**：参考计算机视觉中的 **DETR / YOLO** 范式：
  - 输入长文本 = 图像特征图（Memory Cache），单次前向缓存；
  - 任务类别 = Object Queries，独立可换，与输入分词器解耦；
  - 解码器 = 2~3 层轻量 Cross-Decoder（Self-Attn 学习互斥性 + Cross-Attn 查询文本证据）；
  - 结合常驻学习式背景类（$\varnothing$ / No-Object），杜绝无关输入的强行归类。

## 2. 关键踩坑与诊断记录
- **坑 1：类别概率坍缩（50% vs 50% 假象）**：
  - *现象*：输入 `"你好"` 或 `"我是谁"` 时，模型输出概率固定在 `[0.0, 0.5, 0.0, 0.5]`，训练集 Acc 99% 但测试表现极差。
  - *归因*：直接使用自由随机初始化的 Query 向量，在 Cross-Decoder 深层交互中隐状态余弦相似度收敛、向量平行，导致 Logits 恒等。
  - *修法*：引入 `TextGuidedQueryProjector`，对类别 Query 显式强制做正交初始化（`nn.init.orthogonal_`）并施加 `LayerNorm`，彻底隔绝表征退化。
- **坑 2：伪字符级 Tokenizer（BPE 碎片污染）**：
  - *现象*：初版直接复制的分词器实质为 BPE，内部充满 `['ï¼', 'ä¸', 'ï¼Į']` 等乱码碎片，中文字符被切碎。
  - *修法*：从 nanoSeek 真实对话语料库（7 大对话集）中统计真实高频汉字，提炼出精简统一的 **6000 纯字符级分词器**（16 特殊符 + 121 ASCII/标点 + 5863 常用汉字），做到 1 汉字 = 1 Token。
- **坑 3：模板过拟合与真实语料扩展**：
  - 合成模板缺乏短句和真实多变语境。通过开发 `real_corpus.py` 流水线，从 nanoSeek 语料清洗提取 16,000 条真实长短句，平衡四分类，测试探针准确率由 65% 跃升至 85%，验证集召回率达到 99.8%~100%。

## 3. 下一步演进：YOLO 风格的 [定位 + 类别 + 置信度] 检测头
- 借鉴 YOLO 目标检测模式：`[Bounding Box (start_idx, end_idx) + Category Logits + Objectness Confidence]`。
- 文本决策引擎不仅回答“这句话属于什么类别”，还要主动圈出“是在第几个字符到第几个字符触发了该判定”，真正做到可解释的文本目标检测。
