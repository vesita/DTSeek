# 11 · NDB 适用判据

在 DTSeek 里给某张卡上 NDB（离散、非参数的外部记忆）之前，先回答两个是非题。
**两题都「是」才可能有效**，任一为「否」都是白做。

1. **值是不是按文档局部动态分配的？**
   若「词 → 标签」是全局静态映射，权重本来就能记住，NDB 没有增量信息。
   NDB 唯一不可替代之处，是存**权重无法预存**的文档局部状态。
2. **键是不是显式地址？**
   键必须是字面 / 离散符号这类稳定地址。
   **共指不是表示空间里的相似性**：同一个「他」指 A 或指 B，在冻结隐状态里几乎同分布。
   用语义相似度当键，无论连续还是离散化，都不可靠。

## 三次探索的证据

| 分支 | 判定 | 关键数字 |
|---|---|---|
| 字面情节 NDB（person 卡） | **成立，决定性** | `repeat_mention_acc` 0.375 → 0.843，3 seed Δ=+0.469，极差 0.011；代价 +264 参数 / +34% 步时 / +30MB |
| 全局 NDB（idiom / relation 词表任务） | **否，上界 0.00%** | 换帧探针的单元在训练语料里全覆盖：relation 539/539 词对、idiom 2214/2214 成语（7 seed 未见 ≤4 个 = 0.18%）。失败是「见过没学会」，不是「没见过」 |
| 语义键 NDB（隐状态 → 离散码本） | **否，两头都输** | `repeat` −0.118 / −0.178；`first_mention` −0.122；别名类 −0.086 / −0.206 |

分支一、三共用同一测量台（8 epoch × 150 step，batch 64，`num_layers 2`，同一冻结基座）；
两条校验臂（base / literal）与既有日志**逐位一致**，数字可比。

## 为什么语义键不可能成立

- 别名类重复提及占 **38.4%**（字面同 id 58.7%、字面撞车 2.9%），其中 **91% 是代词**
  （我 454 / 他 132 / 您 112 / 你 108 / 她 96）——它要解决的是**共指**，不是同义改写。
- 原始隐状态的 1-NN 别名召回 0.250~0.275，**低于先验 0.373**（配对 AUC 0.453~0.481）。
  要有信号必须训一个线性度量（真 W：val AUC 0.822；打乱标签对照 0.519）——但**离散化后精度掉光**：
  最好的码本 k-means(8+4) 绝对召回 0.534，只有连续 1-NN 的 69%；单 K=8 是 0.323。
- 更根本的是**码号碰撞**：12 个码号下 82.7% 的别名位置「此前有同码提及」，
  但只有 64.6% 落在同一个人身上——**三分之一是假覆盖**，读门控于是打开、把新人物塞进已有 id。
  离散读救不了它，因为失效来自码号碰撞，不是权重软化。
  表反而小 800 倍（12 槽 vs 12288），这正是覆盖失控的直接原因。

## 反面教训（本主题反复出现的失效模式）

- **软读**：读权重必须是硬的。软 softmax 把首次提及正确率从 0.999 打到 0.480 ——
  权重摊到有键的旧提及上，让「表里根本没有的新人物」也判成已覆盖，门控打开塞一个已有 id。
- **空对照**：`experiments/ndb_semantic/oracle_bound.py` 的「随机特征对照」用的是**正交阵**，
  而正交阵精确保持余弦，其 1-NN 排序与原始必然完全相同——四个设置下对照值与原值**逐位相同**
  （如 `0.25135553834237023`）。**该对照无效，`random_proj_nn1` 不是独立证据。**
  结论不依赖它：先验 0.373 > 召回 0.25、AUC < 0.5、三条臂的 AB 都独立成立。
- **调用口径**：`evaluate_task()` 结尾硬写 `.train()`，而解码器 dropout=0.1；
  调用方若在它之后继续评估，模型处于 train 模式，指标会被污染。

## 先例：nanoSeek 已判死「矩阵参与梯度的记忆」

（引用结论与出处，不复述原文。）

- `nanoSeek/model/neural_db.py`（PK-NDB）**values 参与梯度 ⇒ 撑爆 8G 卡**，模块已删（`nanoSeek/TECH_DEBT.md:336`）。
- `nanoSeek/model/residual_neural_db.py` 实测 Δ→−0.0002（≈0）；ResidualNeuralDB + PKM 记为失败（`nanoSeek/dev-notes/81:1021`）。
- 零梯度的非参数 n-gram 计数表最优：纯检索 n-gram Δ−0.0161，**比残差式好 50×**（`nanoSeek/dev-notes/81:1026`）。
  同组读数：token 级 −0.0161 / 神经元级 −0.0046 / 残差式 −0.0003（`nanoSeek/dev-notes/81:1174`）。
- 机制级解释（`nanoSeek/dev-notes/81:1033-1039`）：写目标取残差 `r = e_y − E_p[e]`，槽位读出 ≈ `E[r|h]`；
  基座在 `h` 下已校准 ⇒ `E[e_y|h] = E_p[e]` ⇒ **`E[r|h] = 0`** ⇒ 注入为零。
  实测注入幅度 11.5% → 1.0%@2000 步 → 0.60%@4000 步，Δ 同步归零。
- 最终唯一保留的载具 `nanoSeek/model/ngram_ndb.py`：**no_grad 计数表（不进 `state_dict`）+ 可学习读写门控**，
  梯度只来自读路径——即「矩阵参与梯度」被降级为「门控参与梯度、表不参与」。

**那条定理对 DTSeek 不适用。** DTSeek 的情节记忆写入的是 `onehot(文档内身份槽)`，
该值按出场顺序**任意分配**，基座不可能预测它 ⇒ `E[r|h] ≠ 0`，且写入是**精确复制**而非残差。
这是判据①在更深的层面上的同一句话：**记忆只能存基座表示不了的东西。**
nanoSeek 的失败是「想存基座已经能预测的关联」；DTSeek 的成功是「存基座无权预测的文档局部指派」。

**MTP 不是记忆。** 它是训练期的多 token 预测辅助头（预测 `t+2`，输出头与 `lm_head` 共享），
在报告 loss 里独占 **25.3%**（`nanoSeek/analysis/NDB_cotrain_STATE_2026-09-10.md:194-203`），
V4.1 论文的做法是 backbone 预训练阶段 omit。它改变的是「模型怎么学」，不是「模型能不能记住没见过的」，
因此不能作为 NDB 的替代路线。可移植的测量教训：**跨臂只比任务指标，不比混合 loss。**

## 判据①的修正：Engram 证明「静态」不等于「权重能替」

判据①原写「静态全局映射权重本来就能记住，NDB 没有增量信息」。这条**过强**。
DeepSeek 的 **Engram**（`arXiv:2601.07372`，ACL 2026 long paper，官方仓库 `deepseek-ai/Engram`，
论文原文已核）证明：静态的 n-gram 查表本身就是一个值得专门做的原语。

- 定位：把经典 N-gram embedding 现代化成 O(1) 查表，作为**与 MoE 正交的第二条稀疏轴**
  （"conditional memory as a complementary sparsity axis"）。
- **表参与梯度**：原文「An All-to-All communication primitive is used to gather active rows in the
  forward pass and **dispatch gradients in the backward pass**」；
  「the **embedding parameters are updated using Adam** … with a learning rate scaled by **5×**
  and no weight decay」（其余参数用 Muon）。
- 但**寻址是确定性的、只依赖输入 token**——"Engram's retrieval indices depend solely on the input
  token sequence"（与 MoE 依赖运行时隐状态相对）。正是这一点让热/冷分层与 host 侧 offload 成立。
- 结果：27B，在**严格 iso-parameter 且 iso-FLOPs** 下胜过 MoE 基线；
  MMLU +3.4 / CMMLU +4.0，而增益更大的是**推理**（BBH +5.0 / ARC-C +3.7）与代码数学
  （HumanEval +3.0 / MATH +2.4）。机制解释：让浅层不必再重建静态模式，把有效深度留给推理。
- 实验设计是关键：把 routed experts 从 72 降到 55，省下的参数**重分配**成 5.7B embedding 模块，
  **总规模恒定** 26.7B。即它不是"加参数"，是"在同预算内换一种稀疏轴"。

所以正确的判据不是「静态 ⇒ 权重能替」，而是：
**权重能存 ≠ 权重用得划算。** 让 FFN/MoE 去「用计算模拟检索」是浪费；给一个专门的 O(1) 查表原语，
在总预算不变的前提下更划算。

由此得到本项目的两条分工（判据①仍然成立，只是要分两种情况）：
- **值的语义是文档局部动态的**（DTSeek 的身份槽 id）→ 权重**无法**预存 ⇒ 表必须非参数，NDB 不可替代。
- **值的语义是全局静态的**（n-gram → embedding）→ 权重能存，但**存得不划算** ⇒ 表应该是**参数**，
  并在 iso-parameter 口径下与"把同等参数给 MoE/头部"做对照。

**直接后果**：`lngtab` 臂（同键、表可学）若只是**加参数**，结论不可解释；
必须有 **iso-parameter 重分配**对照才算数。这条待实验回来后补。

## 参数化 / 可训练记忆对照（提前终止，用已有产物）

口径同上（8 epoch × 150 step，batch 64，`num_layers 2`，同一冻结基座，seed 42/43）。
`literal` = 非参数 NDB。**旁路消融** = 把记忆模块旁路后指标是否变化。

| 臂 | 记忆参数 | seed42 `repeat` | seed43 `repeat` | 旁路消融 |
|---|---|---|---|---|
| base | 0 | 0.3773 | 0.3896 | — |
| **literal（非参数 NDB）** | **264** | **0.8408** | **0.8638** | 非空壳 |
| slots16 | 2,306 | 0.3480 | 0.3922 | **空壳**（旁路后指标完全不变） |
| slots32 | 4,482 | 0.3574 | 0.3850 | **空壳** |
| fastweight | 9,476 | 0.3704 | 0.4004 | 非空壳，≈base |
| fastweight_cls | 9,476 | 0.3562 | — | ≈base |
| lngtab（同键可学习 n-gram 表） | 98,438 | 0.3731 | 0.3671 | **空壳**，门控关到 2.6e-3 |
| ngrammer（局部 n-gram 特征层） | 393,868 | 0.3532 | 0.3908 | ≈base |
| nplm（前馈神经 n-gram） | 279,820 | 0.3590 | — | ≈base |

三条结论：

1. **参数化 / 可训练记忆全部没有超过 base**，而非参数 NDB 是 +0.47。
   参数多 3~1500 倍，结果更差。
2. **`slots` 与 `lngtab` 是空壳**：旁路掉整个记忆模块，全部指标逐位不变。
   `lngtab` 的门控自己关到 **0.0026**，而 `grad_all_nonzero: true` ——
   **梯度在流 ≠ 模块有用**，模型学会了忽略它。这让"非空检验"必须同时查
   ① `grad != 0` ② 旁路后指标确实变化，两条缺一不可。
3. **边界（本实验的规格缺陷）**：这些臂都只是**加参数**，没有 iso-parameter 重分配对照。
   Engram 的证明方式是**同预算重分配**（routed experts 72→55，省下的参数转成 embedding 模块，总规模恒定）。
   所以严格说，本对照否掉的是「**这样加参数**」，不是「n-gram 结构本身无用」。

### 为什么参数化必然输（机制，不只是数字）

- NDB 赢的只有一栏：**`literal_same_id`**（字面同 id）——base .362/.384 → NDB **.9865/.9892**。
  所有参数化臂这一栏停在 **0.32~0.38，与 base 无异**；`alias` 栏（共指）谁都没动。
- `slots` / `diffwrite` **根本没有键**：M 是全局静态矩阵，或只是「本文档已发射过哪些类别」的直方图，
  存不下 `张伟 → 人物1` 这种文档内动态绑定。
- `fastweight` 的键 `k = W_k·h_j` 是**学出来的**：`h_j` 随查询位置与上一步反馈变化，
  同一字面两次出现键就不同。它梯度高达 23~26/步却什么都没换来——在学一个不存在的信号。
- `fastweight_cls` 把值换成 `onehot(cls)`（记忆里终于带 id 了）仍然输 −0.021，
  排除了「只是值没带 id」的辩解：**键非字面 + 软读 ⇒ 新人物被判成已覆盖**。
- **结论：非参数与否不是关键，「离散地址 + 离散读」才是。**
  NDB 的 264 个参数只学「写多重 / 信多少」，内容的寻址不走梯度——这正是它赢的原因。
  这与 Engram 一致：**寻址离散确定、行可以是参数**；DTSeek 的表之所以非参数，是因为它的值是文档局部的。
- 门控不是「没训」，是**模型主动关掉**：`slots` 的 `read_gate.bias` 从 −2.0 被学到 −2.14，
  `last_gate` 塌到 0.004~0.005（NDB 是 0.733）。

### 测量纪律：三个新坑

- **梯度裁剪破坏可比性**：首次 `literal` 复现出 0.8473 ≠ 0.8408，根因是多写了一行
  `clip_grad_norm_(mem.parameters())`，而参考实现只裁 decoder；删掉即逐位复现。
  **对照臂之间的优化器行为必须逐项一致。**
- **空壳检查要两条**：`grad != 0` 与「旁路后指标确实变化」缺一不可
  （`lngtab` 梯度全非零、门控却关到 2.6e-3）。
- `fastweight_cls` 的 `W_v` 是死参数（`grad is None`，白占 1024 参数）。

### 决定性证据：全局表的贝叶斯上界 0.347（封死「只是没训好」）

`experiments/ndb_ngram/oracle_global.py` **不做梯度**，在与 NDB **逐字同源**的键（起始单/双字）上
对训练集计数取后验众数，val 2582 条重复提及：

- unigram **0.3404**、bigram **0.3474**，**键覆盖率 100%**
- ⇒ **任何全局确定性 `key → id` 表的上界 = 0.347 < base 0.377 / 0.390**，远低于 literal 0.841 / 0.864

即：不是「没训好」，是**全局表的贝叶斯最优值本身就低于完全不做记忆**。
机制：正确 id 由**该文档的出场顺序**决定（B 文档里张伟是人物3），全局表没有任何输入能知道这件事。
这是判据①（值必须是文档局部动态分配）的一次**独立正面检验**。

### 收敛结论

三条独立证据指向同一句话：**关键不是「表参不参数化」，而是「寻址是否离散、确定、只依赖输入」。**

| | 寻址 | 行（值） | 结果 |
|---|---|---|---|
| DTSeek NDB（person） | 离散字面 n-gram | **非参数**（文档局部动态 id） | **+0.469** |
| DTSeek 参数化 / 可学习 n-gram 臂 | **学出来的**（`W_k·h`）或无键 | 参数 | ≈base 或**空壳** |
| DeepSeek Engram | **离散确定，只依赖输入 token** | **参数**（Adam 5×、按行稀疏更新） | 27B iso-param 胜 MoE |

## 待办

- **性能**：逐样本表改「文档级预计算键 + 每步 O(1) gather/scatter」。逐位不变已证（12 项指标 +
  `n_written` + `last_gate` + `alpha` + 两个 gate bias 全等），计时待测（需 GPU 空窗）。
  已定位的成因之一：读写里每步约 64 次设备同步（= batch size，逐样本 `.item()`/`float()` 取诊断量）。
- **重构**：NDB 定位为**引擎级设施**，卡只声明「作用域 + 键类型 + 值语义」，
  产物不存私有重建逻辑（现为 `artifacts.py` 的 `extra.ndb` + `engine.py` 的重建分支）。
- **检验点**：按判据，`ownership`（发言归属）是下一个候选——
  先算它的标签是否为文档局部动态分配，再决定要不要训。
  共指类失败（代词链）不属于检索能解决的面，方向是显式喂入引语框架的说话人/受话人结构。
