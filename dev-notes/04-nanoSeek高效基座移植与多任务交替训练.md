# 04-nanoSeek 高效基座移植 + 多任务交替训练（附背景误报根因定位）

本期做了三件事：把 nanoSeek 的实测资产移植进 DTSeek 基座、搭建三任务交替联合训练、
并定位了一个此前一直没被发现的**数据集配比 bug**（它是"中性句乱开火"的真正根因）。

---

## 1. 移植 nanoSeek 高效基座（`src/dtseek/nano_doc_encoder.py`）

旧基座 `SimpleDocEncoder` 是学术玩具配置：LayerNorm + 可学习绝对位置编码 + GELU MLP。
逐项替换为 nanoSeek 已实测验证的组件：

| 组件 | 旧 | 新 | 依据 |
|---|---|---|---|
| 归一化 | LayerNorm（需两次跨通道 reduce） | **RMSNorm**（一次 reduce，无 bias） | `nanoSeek/model/utils.py#RMSNorm` |
| 位置编码 | 可学习绝对位置表（无法外推） | **RoPE 旋转位置编码**（点积自带相对位置 m−n） | `nanoSeek/model/utils.py#precompute_rope_freqs` |
| 注意力稳定 | 无 | **QK-Norm**（q/k 归一到单位球面 + 每头可学温控标量） | `nanoSeek/model/attention.py#use_qk_norm` |
| 前馈 | GELU MLP | **SwiGLU**（SiLU(xW1) ⊙ (xW2)，hidden=8/3·d） | `nanoSeek/model/mlp.py#SwiGLU` |
| 注意力内核 | 手写 QK^T + softmax（显存 O(L²)） | **Flash-SDPA** | `nanoSeek/model/attention.py` flash 分支 |

**唯一结构差异**：nanoSeek 是自回归语言模型（因果掩码），
DTSeek 是决策/切片检测器，需要**双向**上下文（"他"的指代要看后半句），故 `is_causal=False`。

### 实测收益（B=16，同参数量档位）

| 配置 | 旧基座 | 新基座 | 显存变化 |
|---|---|---|---|
| d=128, 3 层, L=64 | 0.51 ms / 53 MB | 1.03 ms / 54 MB | — |
| d=128, 3 层, L=256 | 1.45 ms / 94 MB | 1.78 ms / 73 MB | **−22%** |
| d=128, 3 层, L=512 | 4.22 ms / 207 MB | 4.53 ms / 98 MB | **−53%** |
| d=256, 6 层, L=512 | 22.04 ms / 409 MB | 22.29 ms / 184 MB | **−55%** |

- **显存**：长序列下近乎腰斩（Flash 不落地 L×L 注意力矩阵），可换来更大的 batch；
- **速度**：大 L 基本持平；小 L（≤64）因逐算子 kernel launch 开销略慢 0.5 ms，
  在整轮训练里属噪声级，**不为这点速度牺牲 RoPE/QK-Norm 的正确性与稳定性**；
- **参数量**：encoder 部分 660,608 → 639,884（SwiGLU 在 8/3 配比下比 GELU MLP 更省）。

### 不变量测试（`tests/test_nano_doc_encoder.py`）

- `test_padding_isolation`：打乱 padding 区内容，有效区输出**逐位不变**（diff = 0.0）；
- `test_no_dead_parameters`：全参数都应收到非零梯度；
- `test_rejects_overlong_sequence`：超长序列**显式报错**，不静默截断（静默截断是历史 bug 源头）。

## 2. 多任务交替联合训练（`training/train_multitask.py`）

三张任务卡共享一个基座，每个训练步交替消费三路 batch，基座同时吸收三路梯度
（lr_base=3e-4 稳，lr_head=1e-3 快，余弦退火）：

| 任务卡 | 类别体系 | 数据来源 |
|---|---|---|
| `pronoun` | 无代词 / 第一 / 第二 / 第三人称 | 真实对话挖掘 + 合成 + 中性池 |
| `sentiment` | 中性 / 积极 / 愤怒 / 悲伤 | 真实对话情绪词锚定 |
| `ownership` | 无归属 / 用户 / 助手 / 第三方 | 真实对话角色标识 + 模板 |

**为什么要多任务交替**：单任务训代词，基座只认"我你他"；
单任务训情绪，基座只认"开心难过"。三类任务同时拉扯，基座才被迫提炼
**真正通用的句法/语义特征**——这也是后来位置指针能精确落到"喜欢"上的原因。

## 3. 根因定位：中性句 100% 误报 = 数据集配比 bug

### 症状
用户实测反馈：
```
"你好，你觉得你现在状态怎么样" -> 误报 [6:6] '得' (积极/喜悦)
"我感觉效果好像有点问题"     -> 误报 [11:11] '题' (悲伤/焦虑)
"我有点喜欢这个颜色"         -> 没圈到 '喜欢'，圈成 [8:8] '颜'
```

### 排查
给训练脚本加上**逐任务可判对错的验证指标**（不只是 loss），第一次跑就量化出来了：

```
[pronoun  ] 类别准确率=80.9%  区间完全命中率=11.9%  背景句误报率=100.0%  (n_bg=13)
[sentiment] 类别准确率=42.0%  区间完全命中率= 6.7%  背景句误报率= 52.0%  (n_bg=50)
[ownership] 类别准确率=67.4%  区间完全命中率= 8.3%  背景句误报率=100.0%  (n_bg=19)
```

`背景句误报率=100%` 直接对应用户看到的"乱开火"。

### 根因（`rich_ar_dataset.py` v1）
```python
for _ in range(2500):   # 硬编码 2500 条合成句，全部含代词，从不产背景句
    ...
dataset = bucket_multi + bucket_single + bucket_zero + synthetic_samples
```
- 合成句硬编码 2500 条且**全部含代词**；
- 扫描循环在 `bucket_multi` 满时就 `break`，`bucket_zero` 常常根本没填满；
- 实测 `target=600` 时产出 3169 条，背景句只有 **150 条 = 4.7%**。

模型看到的是"几乎每句都有代词"，于是学会了**永远开火**的退化解。

### 修复
1. **代词数据集**：四类样本按显式配额独立填充（真实 48% / 合成 20% / **背景 32%**），
   扫描循环不再因单个桶满而提前退出；
2. **归属人数据集**：背景配额 10% → **30%**（v1 同样是误报重灾区）；
3. **损失侧**：背景类权重 1.3（背景句在自回归范式下只贡献第 0 步**一个**监督信号，
   但有切片的句子贡献 N 个，天然被双重稀释）。

### 结果（8 epoch，验证集）

| 任务 | 类别准确率 | 区间完全命中率 | 背景句误报率 |
|---|---|---|---|
| pronoun | 96.0% | 96.8% | 1.5% |
| sentiment | 97.6% | 93.1% | 0.0% |
| ownership | 99.8% | 99.5% | 0.0% |

对比修复前：区间命中率 11.9%→96.8%、6.7%→93.1%、8.3%→99.5%；
背景误报率 100%→1.5%、52%→0.0%、100%→0.0%。

### 第二批补丁：分布外句子暴露的覆盖缺口
修完配比后，用户那三句里"喜欢"已精确命中，但仍有两处不理想：
- 中性池只有 12 条**客观陈述句**（"数据库集群写入延迟…"），没有**口语疑问/寒暄**，
  导致"你好，你觉得你现在状态怎么样"被判为积极；
- 归属人训练数据几乎全是 `用户：xxx` / `模型：xxx` 带角色前缀的行，
  演示时喂**裸句**模型只能瞎猜。

补丁：情绪中性池 +30 条口语中性句（疑问/寒暄/流程咨询）；归属人背景池 +15 条裸口语句。
补后再测：

| 测试句 | 修复前 | 现在 |
|---|---|---|
| 我有点喜欢这个颜色 | `[8:8] '颜'` | **`[4:5] '喜欢'` 置信度 0.999** |
| 我感觉效果好像有点问题 | `[11:11] '题'` | 无切片（保守不报） |
| 你好，你觉得你现在状态怎么样 | `[6:6] '得'` 积极 | **无切片** |

## 4. 已知遗留（未解决，如实记录）

1. **同类别重复切片召回下降**：`"你好，你觉得你现在状态怎么样"` 含 3 个"你"，
   多任务版只报出第 1 个（单任务 robust_ar 版能报出 2 个）。
   推测是多任务梯度拉扯降低了自回归步数上的召回，需要专门测"单句同类多实例"召回率。
2. **弱消极情绪偏保守**：`"有点问题"` 这类轻微消极不再触发切片。
   在"乱报"与"漏报"之间当前选择了保守，属于可接受的暂时取舍。
3. 上述两点都是**数据分布**问题而非架构问题，但需用配对实验验证（不能只看单点）。
