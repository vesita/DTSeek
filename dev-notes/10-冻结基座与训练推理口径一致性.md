# 10-冻结基座，以及训练与推理口径必须一致

## 1. 为什么该把基座冻上

加进第 4 张卡（人物追踪）后，前 3 张卡集体退化：

| 任务 | 3 张卡 | 4 张卡（基座可训） |
|---|---|---|
| sentiment | 94.8 / 93.8 | **83.2** / 90.4 |
| relation 对完整命中 | 96.3% | **82.6%** |

共享基座被四路梯度来回拉扯。做法是 `--freeze-base` + `--init-from`：

- `--init-from` 从已有 ckpt **热启动**基座与同名任务头。**冻结随机基座等于让任务头去读噪声**，所以这两个参数几乎总是一起用；
- 基座转 `eval()` 关掉 dropout，前向走 `torch.no_grad()`，不进梯度裁剪。

效果：

| 任务 | 基座可训 | **基座冻结** |
|---|---|---|
| relation 对完整命中 | 82.6% | **92.9%** |
| sentiment | 83.2 / 90.4 | **89.5 / 92.2** |
| pronoun | 98.8 / 99.3 | 99.3 / 99.0 |
| person | 100 / 100 | 100 / 100 |

**而且更快**（16 epoch 6.5 分钟 vs 12 epoch 6.5 分钟）。

原理上的意义：基座一旦冻结，各任务头**彼此完全独立**（唯一的耦合通道就是基座），
互相干扰这件事从根上消失了。

但要注意：冻结的是**当年那个被四路拉扯过的折中基座**，所以各任务仍低于"单独训练"的天花板
（sentiment 89.5 仍低于三卡时代的 94.8）。真正的解法是「联合热身 N epoch → 冻结基座训各头」，
目前只实现了后半段。

## 2. 训练与推理口径必须一致（本轮最大的坑）

`GenericTaskDataset` 是按 `spec.max_len` **整段**编码的，而推理端：

1. `MultiTaskEngine` 对所有任务固定按 55 字切段，**完全无视 `spec.max_len=120`**；
2. 更致命的是 `split_with_global_offsets` **无条件按标点切句**，`max_chunk_len` 只管超长子句。

于是一段 120 字的人物对话在推理时被切成 ~5 个句子、**每句独立解码、id 每句从 1 重来** ——
跨句共指这件事被彻底毁掉。而这一切在训练端看不出来，因为训练是整段喂的。

修法是给 `TaskSpec` 加 `segment_policy`：

- `sentence`（默认）：按标点切句，每句独立解码。适合"每句自成一体"的任务
  （代词 / 情绪 / 词义关系），它们的训练数据本来就是单句；
- `window`：只在超出 `max_len` 时才切，窗口内多句一起解码。人物追踪必须用这个。

数据（人物追踪）：

```
整句一致  0.8%  -> 16.2%
漏标     62.0%  -> 42.7%          （20 倍）
```

**纪律：推理怎么切，必须和训练怎么喂一致。** 这条对任何"需要跨句状态"的任务都成立。

## 3. ckpt 快照校验的粒度：缺字段 ≠ 值不同

加了 `segment_policy` 之后，旧 ckpt 直接加载失败 —— 因为快照里没有这个字段，
`from_snapshot` 默认成 `sentence`，与代码声明的 `window` 冲突。

一开始的校验没区分这两种情况，把"缺字段"也当成漂移。正确的语义是相反的：

| 情况 | 含义 | 行为 |
|---|---|---|
| 字段**缺失** | ckpt 早于该字段诞生，代码里的值就是当前行为 | **继承 + 打印提示** |
| 字段**值不同** | 真的口径漂移（静默跑会让推理与训练不一致） | **报错** |

更进一步：**推理行为归代码，权重语义归 ckpt**。所以现在引擎在通过校验后，
把推理行为类的字段（`INHERITABLE_KEYS`）统一从**注册表里的任务卡**取，
快照只用来校验漂移。类别名 / 类别数 / `max_steps` / `emission` 仍然严格比对，因为它们决定权重含义。

## 4. 整句级指标第四次救命

人物追踪卡报出来的数字：

```
【旧口径】只看首切片：类别 100.0%  区间 100.0%
【真实】  整句完全一致 16.2%       漏标 42.7%
```

首切片必然是对的 —— 第一个人物一定第一个出场，猜都猜得到。**只看首切片的指标在这张卡上等于没测。**

这已经是第四次同一类问题：

| # | 假指标 | 真实 |
|---|---|---|
| 1 | 情绪句级 98% | 词级 43.7% |
| 2 | 词义关系句级 97.9% | 换帧 25.4% |
| 3 | 成语训练集内 83.8% | 换帧 15.0% |
| 4 | 人物首切片 100% | 整句 16.2% |

所以 `evaluate_task` 现在固定报 `exact_match` / `slice_precision` / `slice_recall`，
身份槽任务另外报 `first_mention_acc` / `repeat_mention_acc` / `cluster_f1`。

## 5. 还没解决的

1. **人物追踪漏标 42.7%**：模型没有跨句维持身份状态的能力。`feedback_proj` 只回填"上一步的
   隐状态 + 类别 + 位置"，对 7 个实体的长距离追踪不够。两条路：缩小规模先做通（2–3 人、短段），
   或者把"已分配的 (id, 位置)"作为额外输入喂给下一步。
2. **人物正例 100% 合成**：实测 150 万行对话里「≥2 个名字且无代词」的可验证片段 **0 条**，
   真实语料只能供背景。要真实正例得先有 NER/共指标注。
3. **情绪卡对词典外输入强行给答案**：`认识`（不在 199 词词典里）被判积极 1.00，
   单独的 `不` 被判悲伤 0.94。模型没有"我不知道"这个出口。
