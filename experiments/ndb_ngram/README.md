# 可学习 n-gram 结构 vs 非参数 NDB（person 卡）

**问题**：把 n-gram 做成「可训练的网络结构」（表/层参与梯度），能否达到或超过非参数的
Mention-NDB？

**结论：不能。三个可学习 n-gram 臂全部落在 base 附近，与非参数 NDB 差 −0.46 ~ −0.50 的
`repeat_mention_acc`。** 更关键的是：它们不是「差一点」，而是**空壳** —— 输出置零后指标
逐位不变；且一张在训练集上完美统计的**全局** key→id 表的贝叶斯上界只有 **0.347**，
低于 base（0.377/0.390）。即：**不是没训好，是这类全局表在原理上做不到这件事。**

## 1. 测量台校验（先证明可比）

`ab_ngram.py` 逐行复刻 `training/train_task_card.py` 的初始化与训练顺序。校验臂与参考产物
`/tmp/ab_ndb2/` **逐位一致**：

（首跑 literal 用了 `--lr-mem 1e-3`，与 NDB 门控参考值 3e-4 不同，得 0.8379；改回 3e-4 后
逐位一致。这条也说明测量台对超参敏感、不是巧合命中。）

## 2. 三个可学习臂

| 臂 | 键 | 值 | 参数 |
|---|---|---|---|
| **lngtab** | **与 NDB 逐字相同的 1~2 字前缀哈希** | 全局 `nn.Embedding(slots, 8)`，梯度更新 | 98,438 |
| ngrammer | 局部窗口 `p-1,p,p+1` 的 1~2 阶哈希 | hashed embedding 均值→投影→类偏置 | 393,868 |
| nplm | 提及前 4 字字符嵌入拼接 | 前馈→类分布 | 279,820 |

三者都没有「写」：`write()` 是 no-op，全局参数无法承载随文档重置的情节状态。
参数化臂先用一个同参 `MentionNDB` 占位对象消耗掉与 literal 臂**完全相同**的 RNG，再建真身
并恢复 RNG 状态 —— 下游数据 shuffle 顺序与 literal 逐位相同，配对 Δ 不掺数据顺序噪声。

## 4. 独立上界：任何全局 key→id 表的天花板是 0.347

`oracle_global.py` 不做梯度：在训练集（8100 样本）上对**与 NDB/lngtab 逐字同源的键**
（起始单字 / 起始双字）计数，取后验众数，在 val（900 样本，2582 条重复提及）上评。
这是**任何**确定性全局表（含容量无穷、完美拟合的全局表）的贝叶斯上界。

| 全局表 | 键覆盖率 | repeat 合计 | 字面同 id 类 | 别名类 |
|---|---|---|---|---|
| unigram | 1.0000 | **0.3404** | 0.3413 | 0.3377 |
| bigram | 1.0000 | **0.3474** | 0.3518 | 0.3397 |

键覆盖率 100%（不存在「没见过所以查不到」的借口）。**上界 0.347 < base 0.377/0.390**，
远低于 literal 0.841/0.864。这解释了为什么 lngtab 贴着 base：它学到的就是 id 的边缘分布。

## 5. 非空检验：梯度非零，但臂是**空壳**

每个参数化臂的所有参数都拿到非零梯度（`grad_all_nonzero=True`，`grad_per_param` 见
`results.json`）：

| arm | grad 均值 | 表/嵌入 | read_gate |
|---|---|---|---|
| lngtab | 0.34 ~ 0.66 | `emb.0/1` 0.0004 ~ 0.0041 | 0.04 ~ 0.31 |
| ngrammer | 1.72 / 1.73 | `emb.weight` 0.17 ~ 0.28 | 1.18 / 1.75 |
| nplm | 3.51 | `emb.weight` 0.74 | 1.98 |

lngtab 的表梯度很小（且 lr 从 3e-4 提到 1e-3 指标仅 +0.006），但**上界证明这无关紧要**：
即使完美拟合也只有 0.347。

**旁路消融（输出置零后重评）—— 决定性：**

| arm | seed | 正常 | 旁路 | Δ |
|---|---|---|---|---|
| lngtab | 42 | 0.3731 | 0.3731 | **+0.0000** |
| lngtab (3e-4) | 42 | 0.3790 | 0.3790 | **+0.0000** |
| lngtab | 43 | 0.3671 | 0.3671 | **+0.0000** |
| ngrammer | 42 | 0.3532 | 0.3525 | −0.0006 |
| ngrammer | 43 | 0.3908 | 0.3873 | −0.0035 |
| nplm | 42 | 0.3590 | 0.3600 | +0.0010 |

**把三个臂的输出全部置零，指标几乎逐位不变** —— 解码器根本没在用它们；梯度非零是因为
梯度确实流回了参数，但参数对最终决策没有可测影响。按验收标准：**三个臂都是空壳。**
（对照：literal 的贡献是 Δ(base)= +0.469，不是空壳。）

## 7. 单独回答父代理的待验证推论

> person 的 id 按文档出场顺序分配，所以任何全局共享的可学习 n-gram 表在原理上只能学 id 的
> 边缘分布。`lngtab` 是明显弱于 `literal` 吗？弱多少？

**是，且不只是「弱」—— 它对任务是零贡献。**

- 弱多少：`repeat_mention_acc` **−0.462 / −0.497**（seed42/43）；`cluster_f1` −0.450/−0.472；
  `first_mention_acc` −0.137/−0.124；字面同 id 类 −0.621/−0.633。
- 绝对水平：lngtab 0.373/0.367/0.379，与 base 0.377/0.390 同档（Δ ≤ 0.023，两个 seed 方向不一致）。
- 别名类几乎没有净改善（lngtab 0.433/0.389 vs base 0.418/0.396 vs literal 0.444/0.553）。
- **机制**：`literal_same_id` 是 NDB 的主战场（0.986/0.989 vs base 0.362/0.384），
  而全局表在这一栏只有 0.34~0.35（oracle 上界）。全局表把「张伟」映到固定的 id 边缘分布，
  而正确的 id 由**该文档内的出场顺序**决定 —— 这是文档局部状态，不是字面属性。
  B 文档里张伟=人物3，全局表没有任何输入能告诉它这一点。
- 这是对 **NDB 适用判据①（值必须是文档局部动态分配）** 的一次独立正面检验：判据成立。
  全局表连 base 都追不上（上界 0.347 < base 0.377），更谈不上 NDB。

## 8. 限制与未完成项（诚实清单）

1. **nplm seed43 与 lngtab `--freeze-mem`（从优化器移除）未完成**：两次都在启动后 1~60 秒内
   被外部 SIGTERM 杀掉（日志为空，退出码 143），重试仍在 1~2 秒内被同样杀掉。旁路消融
   （输出置零）已覆盖「确认指标下降」这一验收要求，结论不依赖缺失的 freeze 臂。
2. **lngtab 表梯度偏小**（`emb` 0.0004~0.0041），所以「lngtab 只是没训动」是一个合理质疑 ——
   §4 的贝叶斯上界正是为封死这个漏洞而做：完美拟合也只有 0.347。
3. **键空间差异**：ngrammer/nplm 的键与 NDB 不完全相同（前者含后文窗口、后者取向相反），
   只有 lngtab 是「键逐字相同、唯一变量是值是否可学」的干净对照。结论以 lngtab 为准。
4. **注入点**：测量台（`src/dtseek/tasks/runtime.py`）只提供「混入类别 logits」这一个挂载点，
   且 `src/` 只读。所以 ngrammer 的「混入解码器输入特征」被改成混入类别 logits，不等价。
5. **lngtab 用了对参数化臂更有利的 lr**（1e-3 vs NDB 门控 3e-4），仍输 → 结论是保守的。
6. **没有 commit**；只在 `experiments/ndb_ngram/` 下新建文件。
