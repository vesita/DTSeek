# 参数化 / 可微记忆 vs 非参数 NDB（person 卡）

## 要回答的问题

> 让记忆矩阵参与梯度计算（常见的参数化 / 可微记忆），在这个任务上能否达到或超过 NDB？

**结论：不能。三条参数化臂都没超过 base，离 literal-NDB 差 ~0.47。**
不是「没效果」，是**结构性不可能**：它们没有「字面地址」这个键。

---

## 受控条件

同一冻结基座 `checkpoints/base_encoder.pt`、同一数据、`--epochs 8 --steps-per-epoch 150`、
`batch 64`、`num_layers 2`、seed 42/43。每条臂构造记忆模块时**不消耗全局 RNG**
（`memories.py` 用局部 `torch.Generator`；`nn.Linear.__init__` 的 `reset_parameters()`
会偷吃全局 RNG，已用 `get/set_rng_state` 围起来），所以三个参数化臂与 `base` 臂
**共享同一条全局 RNG 轨迹**（同样洗牌、同样 dropout），配对性比与 `literal` 臂更强。

`base` / `literal` 复用 `/tmp/ab_ndb2/*.log`，未重跑（只跑了一次校验）。

## 硬守卫 4：首次提及不能恶化

所有参数化臂 `first_mention_acc` 0.8464~0.8795，相对 base 0.8597/0.8658 变化 ≤0.013，
唯一一手坏的是 fastweight_cls seed42（0.8464，−0.0133）。**没有出现语义键那种
0.999→0.480 的崩塌** —— 因为这些臂的读门控初始就是 σ(−2)≈0.12、且 `covered=0` 时强制关，
第 0 步完全走模型自己。代价是：它们也因此从没真正打开过。

## 机制解释：为什么参数化记忆赢不了

NDB 赢的那一栏是 **`literal_same_id`**（字面同 id）：base 0.3622/0.3839 → NDB
**0.9865/0.9892**。所有参数化臂在这一栏是 **0.32~0.38，与 base 无异**。
`alias`（代词共指）栏谁都没动（0.39~0.55），这不是记忆能解决的，是共指表示问题。

1. **`slots` / `diffwrite` 根本没有键。** `M ∈ R^{S×C}` 是全局静态的，同一篇文档里第 1 次
   和第 5 次提及看到的是同一张矩阵，区别只来自隐状态 h；`diffwrite` 的 M 只是
   「本文档已发射过哪些类别」的直方图（`M ∈ R^{B×C}`，无键维），与「哪个字面 → 哪个 id」
   无关。没有字面地址，就存不下 `张伟→人物1` 这种文档内动态绑定。
2. **`fastweight` 的键是学出来的，不是字面地址。** `k = W_k h_j`，而 `h_j` 是解码器第 j 步
   的隐状态，随查询位置、上一步反馈、模型自己的不确定性而变。同一个「张伟」两次出现，
   两次的 `h` 不同 → 键不同 → 外积检索对不上。共指不是表示空间里的相似性
   （`dev-notes/11` 已证：原始隐状态 1-NN 别名召回 0.25 < 先验 0.373，配对 AUC < 0.5）。
   把键换成「学习投影」只是把不可靠的相似度再乘一个线性层。**这个梯度很大（23~26/步）
   却什么也没换来**，正说明它努力在学一个不存在的信号。
3. **`fastweight_cls` 把值换成 `onehot(cls)`，记忆里终于有 id 了，结果仍然输**（−0.021）。
   这排除了「只是值没带 id」这个辩解：键仍然不是字面地址，软的键 + 软的读会把
   「新人物」判成「已覆盖」（`dev-notes/11` 记录过：软读把 first_mention 从 0.999 打到
   0.480，因为权重摊到有键的旧提及上）。
4. **非参数与否不是关键，「离散地址 + 离散读」才是。** 三条臂都有梯度、都非空，
   但要么把门自学到关（slots），要么学出一个噪声（fastweight）。NDB 的 264 个参数
   只学「写多重 / 信多少」，**内容的寻址不走梯度**——这正是它赢的原因。

## 代价（★ 计时不干净）

GPU 全程有他人计算进程（每次训练前快照：2.2~3.2 GB 已用、2%~52% 利用率，
见 `logs/gpu_snapshots.txt`；另有一个子代理在同卡做 NDB 步时探针并在留言板声明了窗口）。
**`sec_per_step` 不可当干净数据**，只能说量级：slots16/slots32 ≈ 0.108~0.115，
fastweight ≈ 0.120，literal ≈ 0.106~0.109，base ≈ 0.081~0.082（base 是复用日志，
来自更早的空窗）。峰值显存：base 676 MB，slots 677 MB，fastweight 682 MB，
literal 706 MB。参数量：slots16 2306 / slots32 4482 / fastweight 9476 / literal 264。

## 没做完的部分（诚实交代）

- **`diffwrite` 无有效结果。** 首轮两 seed 因 `read_gate` 维度写错（`_mix` 的门控输入是
  `[h, log1p(total), covered]` = D+2，我建成了 D+1）瞬间退出；修好后两次补跑
  （20:00:40、20:00:47 两个窗口）都在启动数秒后被**外部 SIGTERM** 杀掉，日志 0 字节，
  随后用户叫停。CPU 自检证明该臂接口、形状、梯度、旁路都正常，但**没有端到端指标**。
  机制上它最像 NDB 却仍然**无键**，预期落在 slots 与 base 之间。
- **`fastweight_cls` 只有 seed 42。** seed 43 在首轮被 SIGTERM（exit 143），未补跑。
- **`fastweight_cls` 的 `W_v` 是死参数**（值来自 `onehot(cls)`，该投影用不到，
  `grad is None`，白占 1024 个参数）。刻意保留它（而不是删掉）是为了让代码与已产出的
  seed42 结果逐位对应；`test_memories_cpu.py` 显式把它列为例外。
- 结论置信度：`slots16/32`（2 seed，Δ 一致为负）与 `fastweight`（2 seed，Δ 换号≈0）
  是可信的；`fastweight_cls` 只有 1 seed，只能作旁证。

## 文件

- `memories.py` —— 三个记忆臂，与 `MentionNDB` **逐接口同构**（`reset`/`read_attention`/
  `read`/`write_enabled`/`write`），因此 `runtime.py` 一行都不用改。
- `ab_parametric.py` —— 受控 AB（复刻 `train_task_card.py` 的 RNG 顺序；自带测量台校验口令）。
- `test_memories_cpu.py` —— CPU 自检：形状 / 梯度非空 / 旁路 / 全局 RNG 不被消耗。
- `run_all.sh` / `run_rest.sh` —— 批量跑（后者带重试，对付外部 SIGTERM）。
- `consolidate.py` —— 汇总参考臂日志 + 本目录 json → `summary_table.txt` / `results.json`。
- `results/` `logs/` —— 每条臂逐 seed 的原始 json 与日志。
- 未改 `src/`、`scripts/`、`training/`、`tests/`、`checkpoints/`、`release/`（mtime 可核）。
